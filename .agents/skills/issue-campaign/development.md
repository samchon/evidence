# Campaign Implementation

Use this procedure only for an authorized issue-to-implementation campaign. The development, review, and pull-request skills retain ownership of their ordinary rules.

Translate the accepted issue set into a dependency order and identify independently reviewable implementation units. Respect the user's chosen PR grouping. The roadmap owns execution order when early planning-only prerequisites differ from that order.

Keep an acceptance ledger for every issue in scope. Land the implementation and its meaningful regressions together; do not defer testing until the entire campaign is finished. Preserve unchanged behavior and record intentional migration differences.

Before submission, verify the complete integrated change, including packaging and public documentation. A clean CI result and a complete self-review are separate evidence. Resolve verified findings and recheck the corrected head.

Use closing references only for issues the final diff resolves. An issue that becomes invalid, incomplete, or externally blocked needs an explicit disposition, not a misleading closing keyword. Continue the next campaign cycle only when the user's mandate includes it. PR submission alone does not authorize merge or renewed issue publication.
