# Multi-Agent Workflows

Read the base workflow first. For parallel review read [review.md](review.md); for parallel implementation or a campaign read [implementation.md](implementation.md). These procedures do not widen the task or authorize external actions.

Use only agents with an immediately useful, bounded assignment. Available capacity is not a reason to delegate. Keep the lead working on independent verification, integration, and decisions instead of duplicating an assigned task.

Give each agent the user's objective, current constraints, relevant rules, expected result, and owned surface. Do not permit uncoordinated writes to shared package metadata, lockfiles, or generated outputs. The lead owns integration and the final report.

Keep agent work inside the current checkout where ownership can be maintained safely. Do not disturb unrelated user work or let agents invent a new branch topology. Do not delegate further unless the user's requested workflow supports it and the resulting assignment is concrete.
